The “Harvest Now, Decrypt Later” (HNDL) threat poses a long-term confidentiality risk when adversaries capture encrypted data for later decryption using quantum computers; furthermore, third-party cloud storage can introduce concerns regarding metadata, access control, and data governance. This paper presents MonoLog, a peer-to-peer data-synchronization prototype designed to provide locally managed data storage without a central service. MonoLog uses an append-only container format (.scaf), designed to support crash recovery, across a local device mesh. Its hybrid cryptographic architecture uses ephemeral ML-KEM-based key establishment, standardized in NIST FIPS 203, together with explicit key-erasure procedures designed to provide forward secrecy. It also utilizes ML-DSA, standardized in NIST FIPS 204, to provide digital signatures that enable peer authentication and message-signature verification. AES-256-GCM, specified in NIST SP 800-38D, provides authenticated bulk-data encryption using a unique 96-bit nonce and authentication-tag verification for each encrypted data chunk. MonoLog implements a state-compacted synchronization ledger and a deterministic reconciliation procedure designed to allow concurrent offline edits while reducing synchronization metadata relative to selected CRDT baselines. Performance evaluations over local wireless networks demonstrate viable synchronization performance and successful reconciliation of concurrent offline edits under the evaluated workloads. With an asynchronous graphical interface, this work presents MonoLog as a prototype pathway toward a more usable, locally managed, and post-quantum-aware file-storage system.
